# 计费说明

本文说明 SSE API 开放平台如何根据上游返回的 `usage` 计费，以及缓存命中、多模态图片等规则。

## 计费来源

优先使用上游（vLLM / OpenAI 兼容服务）返回的 `usage`：

- 非流式：响应 JSON 的 `usage`
- 流式：平台会强制 `stream_options.include_usage=true`，解析 SSE **末包**中的 `usage`

若上游未返回可用 usage，平台会用 messages + 输出文本做**粗估**（会去掉图片 base64，避免体积暴涨），并在用量日志中标记 `usage_estimated`。

## Token 拆分

| 项 | 计算 |
| --- | --- |
| Prompt | `usage.prompt_tokens` |
| 缓存命中 | `usage.prompt_tokens_details.cached_tokens`（不超过 prompt） |
| 未命中输入 | `prompt_tokens - cached_tokens` |
| Completion | `usage.completion_tokens` |

## 价格公式

单价均为 **¥ / 1M tokens**（管理员在管理台配置）：

```
cost_cents = ceil(
  ( fresh_tokens × input_price_per_1m
  + cached_tokens × cache_price_per_1m
  + completion_tokens × output_price_per_1m
  + 图片token附加（若有）
  ) / 10000
) + 按张图片费用（若有，¥→分再 ceil）
```

等价理解：先算「元」再 ×100 并向上取整到「分」。

### 示例

假设：输入价 1、缓存价 0.1、输出价 2（¥/1M）；某次 `prompt=1_000_000`，其中一半缓存命中，无输出：

- 未命中 500_000 × 1 + 命中 500_000 × 0.1 = 550_000（按公式路径）→ **55 分（¥0.55）**

缓存价为 `0.001` 时同样适用上述公式（管理台支持 `0.001` 步进录入）。

## 多模态图片计费

管理员可为模型开启多模态，并选择：

### 1. 按 token（默认）

图片通常已计入上游 `prompt_tokens`，按输入 / 缓存价计费。  
若上游拆出 `image_tokens`（或同类字段）且配置了「图片 token 价」，则图片 token 按该价，并从输入未命中中扣除，避免双重计费。

### 2. 按张数

- 平台统计 messages 中 `type=image_url`（及兼容类型）的张数
- 另收：`张数 × 图片单价（¥/张）`
- 同时从 prompt 扣除 `张数 × 每图预估 tokens`（默认 512，可配），减少与上游图 token 的双重计费

未开启多模态却传图 → **HTTP 400**（`multimodal_not_enabled`）。

## 余额与流水

- 控制台 **余额与流水** 可查看充值 / 扣费明细
- **用量** 可按日、按模型、按调用查看 prompt / 缓存 / completion / 图片张数与费用
- 余额 ≤ 0 时调用返回 **402 insufficient_quota**

充值请联系平台管理员。
