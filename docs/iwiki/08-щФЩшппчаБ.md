# 错误码

调用 `https://api.ssemarket.cn/v1/*` 时，错误通常以 JSON 返回：

```json
{
  "error": {
    "message": "人类可读说明",
    "type": "error_type"
  }
}
```

## HTTP 状态一览

| HTTP | type（常见） | 含义 | 处理建议 |
| --- | --- | --- | --- |
| 400 | `invalid_request_error` | 缺 `model` 等参数 | 检查请求体 |
| 400 | `multimodal_not_enabled` | 模型未开多模态却传了图片 | 去掉 image_url 或换多模态模型 |
| 401 | — | API Key 无效 / 已吊销 | 重新创建密钥 |
| 402 | `insufficient_quota` | 余额不足 | 联系管理员充值 |
| 403 | `origin_forbidden` | Origin/Referer 未命中白名单 | 调整域名限制或改服务端调用 |
| 404 | `not_found` | 模型不存在或未启用 | 核对 slug；`GET /v1/models` |
| 429 | — | RPM 或并发超限 | 降速 / 申请提高限额 |
| 502 | `upstream_error` | 上游连接失败 | 检查 vLLM / 上游地址 |
| 503 | `upstream_not_configured` | 模型未配置上游 Base URL | 联系管理员 |

## 控制台相关

控制台（`platform.ssemarket.cn`）走 Cookie / JWT，与 API Key 体系分离：

| 场景 | 说明 |
| --- | --- |
| 未登录 | 跳转 OAuth 登录 |
| 非管理员访问管理台 | 回到概览 |

## 排查清单

1. Key 是否复制完整、未吊销  
2. `model` 是否等于控制台 Slug  
3. Base URL 是否为 `https://api.ssemarket.cn/v1`（注意含 `/v1`）  
4. 余额是否 > 0  
5. 浏览器调用是否命中域名白名单  
6. 多模态是否已开启  

仍异常时，把请求时间、模型 slug、HTTP 状态与 `error.message` 发给管理员，并对照控制台 **用量** 日志。
