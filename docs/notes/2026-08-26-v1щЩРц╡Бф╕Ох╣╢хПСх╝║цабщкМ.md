# API Platform：/v1 限流与并发强校验

> 日期：2026-08-26

## 背景

需在 **后端 `/v1` 代理** 强制 RPM 与并发限制，管理员可配置全局默认及用户/模型级覆盖。

## 实现

### 校验位置

`server/src/routes/proxy.ts`：`GET /v1/models`、`POST /v1/chat/completions` 在鉴权后调用 `enforceRateLimits()`。

### 策略（多层叠加，均需通过）

| 维度 | 桶键 | 配置来源 |
|------|------|----------|
| 用户 | `rpm:user:{id}` / `conc:user:{id}` | 用户 `rpm_limit` / `max_concurrent`；0=继承平台默认 |
| 密钥 | `rpm:key:{id}` / `conc:key:{id}` | 密钥字段；用户 PATCH `/api/keys/:id` 可设 |
| 模型 | `rpm:model:{slug}` / `conc:model:{slug}` | 管理台模型表单 |

平台默认存 `store.rate_limits`：`enabled`、`default_rpm`（默认 60）、`default_max_concurrent`（默认 2）。

环境变量（冷启动/缺省时）：`SSEAPI_RATE_LIMIT_ENABLED`、`SSEAPI_DEFAULT_RPM`、`SSEAPI_DEFAULT_MAX_CONCURRENT`。

### 拒绝响应

HTTP **429**，OpenAI 风格 body + `Retry-After` 头：

```json
{"error":{"message":"用户请求过于频繁（RPM 60）","type":"rate_limit_exceeded","code":"rate_limit_exceeded"}}
```

### 管理台

- **限流** Tab：全局开关、默认 RPM/并发
- **模型** 表单：模型 RPM/并发
- **用户** →「限流」：单独覆盖

### 限制说明

- 计数器在 **单 Pod 进程内存**，多副本时限流为「每副本独立」；要集群级需后续接 Redis
- 流式响应占用并发直至 `finish`/`close`
