# 多模态计费与细粒度缓存价

## 背景

1. 多模态模型需识别请求中 `image_url` 张数，并支持按 token 或按张计费。  
2. 缓存命中单价需支持 `0.001` 这类细粒度（原管理台 `step=0.01` 不便录入）。

## 结论

### 多模态

- 模型字段：`multimodal_enabled`、`image_billing_mode`（`token`|`per_image`）、`image_price_per_1m`、`image_price_per_image`、`image_tokens_per_image`（默认 512）
- 代理：统计 messages 内图片张数；未开多模态却传图 → 400；透传上游；usage 记 `image_count`
- **按 token**：图片一般已计入上游 `prompt_tokens`；若 usage 拆出 `image_tokens` 且配置了图片 token 价则按该价并从输入未命中中扣除
- **按张**：另收 `张数 × ¥/张`，并从 prompt 扣除 `张数 × image_tokens_per_image` 防双重计费
- 无 usage 粗估时会 redact base64，避免体积暴涨

### 缓存价 0.001

- 管理台输入/缓存/输出/`图片` 单价 `step="0.001"`
- `calcCostCents` 本就支持任意浮点单价；1M 全缓存 @ 0.001 → 1 分

## 关键路径

- `server/src/services/multimodal.ts`、`users.ts`、`routes/proxy.ts`、`db.ts`
- `admin.ts` / `models.ts`、AdminView / ModelsView / UsageView
- 默认文档增加多模态 curl 示例

## 验证

管理台开启多模态 → 配置计费方式 → 用 image_url 调 `chat/completions` → 用量日志有图片列。缓存价可填 `0.001` 并保存。
