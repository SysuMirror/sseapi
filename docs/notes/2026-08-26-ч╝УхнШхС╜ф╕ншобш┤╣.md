# 缓存命中计费（prompt_tokens_details.cached_tokens）

## 背景

vLLM 返回：

```json
"usage": {
  "prompt_tokens": 1120,
  "completion_tokens": 24,
  "prompt_tokens_details": { "cached_tokens": 784 }
}
```

流式在 `stream_options.include_usage: true` 的末包同样带该结构。

## 计费公式

管理员为模型配置三档单价（¥ / 1M tokens）：

| 项 | 数量 | 单价字段 |
|----|------|----------|
| 未命中输入 | `prompt_tokens - cached_tokens` | `input_price_per_1m` |
| 命中缓存 | `cached_tokens` | `cache_price_per_1m` |
| 输出 | `completion_tokens` | `output_price_per_1m` |

例：1120 prompt、784 cached、24 completion → 计费 `(336×输入 + 784×缓存 + 24×输出) / 1e6` 元，再 `ceil` 到分。

## 改动

- 模型：`cache_price_per_1m`；管理台「缓存价」；用户模型卡展示
- usage_log：`cached_tokens`；用量页增加「缓存」列
- `calcCostCents` / proxy `readUsage` 解析 `prompt_tokens_details.cached_tokens`
- 迁移：旧模型缺省缓存价 `0`（命中免费，需管理员改价）

## 验证

1. 管理台编辑模型设缓存价 → 保存
2. 重复长 prompt 调用（非流/流式均可），确认 usage 有 `cached_tokens`
3. 用量日志：`cached_tokens` 非 0，费用低于「全部按输入价」
