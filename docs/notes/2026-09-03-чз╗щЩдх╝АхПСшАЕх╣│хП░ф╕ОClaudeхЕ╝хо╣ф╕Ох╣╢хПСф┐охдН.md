# 2026-09-03 移除开发者平台 / Claude 协议兼容 / 并发限流修复

## 背景

用户要求：去掉 `api-platform` 里的开发者相关部分（开发者工作台/模块注册/开发者应用等）；给配置的模型添加 Claude 协议兼容（底层模型方先做兼容，平台做兼容转发）；并打成可部署压缩包。

之后反馈并发问题：设置了模型并发=100，但只开了 3 个对话就报 `密钥并发已满（上限 2）`。

## 结论

### 1. 移除开发者平台

后端（`server/src`）：
- 删除路由：`routes/developer.ts`、`routes/developers.ts`、`routes/dev-modules.ts`
- 删除服务：`services/developer-platform.ts`
- `db.ts`：删除 `PlatformEntryRow`/`DevModuleRow`/`DevApplicationRow` 类型与 `platform_entries`/`dev_modules`/`dev_applications` 表，删除 `seedDeveloperPlatform()`，移除 `UserRow.is_developer`
- `middleware/auth.ts`：移除 `requireDeveloper`/`isDeveloperUser`/`optionalAuthJwt`
- `services/users.ts`：移除 `publicDeveloperBrief`/`developerCheckPayload` 及 `is_developer` 相关
- `routes/admin.ts`：移除 `/developers`、`/platform-entries`、`/dev-modules`、`/developer-applications` 相关路由及 adminStats 中的开发者字段

前端（`web/src`）：
- 删除视图：`DeveloperHubView.vue`、`DevModulesView.vue`
- 删除组件：`DeveloperJoinCta.vue`、`admin/AdminDevelopersPanel.vue`、`admin/AdminDevModulesPanel.vue`、`admin/AdminDevApplicationsPanel.vue`、`admin/AdminEntriesPanel.vue`
- `router/index.ts` 移除 `/developer`、`/developer/modules`
- `components/AppShell.vue`、`views/OverviewView.vue` 移除开发者入口/横幅
- `api/index.ts`、`store/auth.ts` 移除对应方法与 `isDeveloper` 字段

### 2. Claude 协议兼容转发

新增 `services/claude-adapter.ts`，在 `routes/proxy.ts` 增加 `POST /v1/messages`：
- `claudeRequestToOpenAi`：Claude Messages 请求 → OpenAI Chat Completions（system 独立、content block 文本/图片 base64→`image_url` data URI、thinking budget→`enable_thinking`、stop_sequences→stop）
- `openAiResponseToClaude`：OpenAI 非流式响应 → Claude `{type:"message", content:[{type:"text"}], stop_reason, usage}`
- `openAiStreamChunkToClaude` / `claudeStreamStartEvents`：OpenAI SSE → Claude 流式事件（`message_start`→`content_block_start`→`content_block_delta`→`message_delta`→`message_stop`）
- 计费沿用 `settleBilling`/`readUsage`，图片按 `countClaudeImages`

数据模型与开关：
- `db.ts` `ModelRow` 增加 `claude_compat`
- `model-catalog.ts`：`capabilities.claude`、`mapModelConsole.claudeCompat` 暴露
- 前端 `AdminView.vue` 模型编辑增加「Claude 协议兼容」开关与标签；`ModelsView.vue` 展示 `Claude` 标签与 `/v1/messages` 路径

仅 `chat` 类型且开启 `claude_compat` 的模型才暴露 `/v1/messages`，其余走 `/v1/chat/completions`。

### 3. 并发限流修复

`services/rate-limits.ts`：原逻辑对用户/密钥/模型三层分别用「默认值」填充 `max_concurrent`/`rpm`，再取全部通过的 **min**，导致模型设 100 也被用户/密钥的默认 2 压低。改为：**仅当没有任何一层显式设置时**才用全局默认兜底；某层显式设更高值（如模型 100）不再被默认 2 压低。

## 验证

- `server`：`npm run build`（tsc）通过
- `web`：`npm run build`（vue-tsc + vite）通过
- E2E 冒烟：mock OpenAI 上游 + 真实 `POST /v1/messages`，非流式返回 Claude 形状、流式返回完整 SSE 事件序列、`/v1/chat/completions` 仍正常
- 并发逻辑：场景 model=100/user=0/key=0 → 有效并发 100；全 0 → 默认 2 兜底

## 打包

- `deploy/pack-sseinfra.ps1` → `sseapi-sseinfra.zip`（0.43 MB，含 server/dist + web/dist 预构建，src 齐全，无 developer 残留，含 `server/src/services/claude-adapter.ts` 与 `server/dist/services/claude-adapter.js`）

## 未决 / 注意

- 并发计数 `concurrentCounts` 是进程内存态：单副本 OK，多副本部署不共享计数（可能超卖）。如需多副本墙，需引入 Redis 等共享计数。
- `claude_compat` 依赖底层 vLLM/上游已完成 Claude 兼容（字段映射在平台层，是否原生支持由上游决定）。
- 老库升级：`db.ts` migrate 会给历史模型补 `claude_compat=0`，需在管理台手动开启。
