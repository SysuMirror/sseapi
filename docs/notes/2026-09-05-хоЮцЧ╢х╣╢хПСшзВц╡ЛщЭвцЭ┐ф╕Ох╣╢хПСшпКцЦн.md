# 2026-09-05 实时并发观测面板 + 并发控制诊断

## 背景

用户问「并发是否有问题（包括全局并发），需要面板能看到当前状态、各个 API 的并发」。

需要：
1. 审查并发控制是否有问题，特别是「全局并发」与「模型设 100 却只跑 2」现象。
2. 提供一个管理面板，实时展示全局 / 各端点 / 各模型 / 各用户 / 各密钥的「当前并发数 / 上限」。

## 并发控制现状 / 诊断

并发闸门在 `server/src/services/rate-limits.ts` 的 `enforceRateLimits`（`/v1/*` 各入口调用）。核心是**按维度独立计数**：

- `conc:user:<id>`（用户）、`conc:key:<id>`（密钥）、`conc:model:<slug>`（模型）。
- 三者是 **AND 关系**：任一维度满即拒绝（429）。因此**实际并发 = 所有配置了上限的维度取最小值**。
- 全局默认 `default_max_concurrent` 只在「用户/密钥/模型三层都未显式设并发」时才作为唯一闸门。

**「模型设 100 却只跑 2」根因**：不是模型层被压，而是**名下用户或密钥层设了更小并发**（含历史默认值），导致 `min(用户, 密钥, 模型)` 变小。一旦用户/密钥层显示值存在，模型层的 100 就无法生效。

**关于「全局并发」**：当前没有独立的总并发闸门；`default_max_concurrent` 只作兜底。经与用户确认，本轮把「全局并发」作为**观察指标**（仅展示当前总数，不新增限流闸门），各层限流仍按 用户/密钥/模型 各自执行。

## 结论 / 方案

1. **新增实时并发观测**（不做拦截，独立于限流闸门）：
   - `trackEndpoint(endpointName)`：为某端点启用「当前活跃请求」计数（含全局 `all`）。返回幂等释放函数，挂在 `res.once('close')` 与 `res.once('finish')`，流式请求结束/断开均能正确释放，不泄漏。
   - `getRuntimeStatus()`：返回 `{ global, endpoints, models, users, keys, defaults }`，每项含 `current` 与 `limit`（模型/用户/密钥的上限取自各自 `max_concurrent`；0=不限）。
2. **管理路由**：`GET /api/admin/rate-limits/status`（JWT + admin）返回 `getRuntimeStatus()`。
3. **前端面板**（`AdminView.vue`「限流」Tab）：
   - 顶部展示「全局并发（所有 /v1）」当前数。
   - 按端点 / 按模型 / 按用户 / 按密钥 四张表，显示「当前 / 上限」。
   - 自动刷新（2s，可关）+ 手动刷新按钮。
   - 提示「模型并发会被名下用户/密钥的并发上限压住（三者取小）」。

## 关键文件

- `server/src/services/rate-limits.ts`：新增 `trackEndpoint`、`endpointActive`/`globalActive` 计数、`getRuntimeStatus`。
- `server/src/routes/proxy.ts`：`/models`、`/models/:modelId`、`/chat/completions`、`/embeddings`、`/images/generations`、`/messages`、`/responses` 各入口接入 `trackEndpoint`。
- `server/src/routes/admin.ts`：新增 `GET /rate-limits/status`。
- `web/src/api/index.ts`：新增 `adminRateLimitsStatus`。
- `web/src/views/AdminView.vue`：限流 Tab 增加实时并发面板 + 2s 轮询 + 样式。

## 验证

- `server`: `npx tsc` 通过。
- `web`: `npm run build` 通过。
- `server/.e2e-test/run-protocol.mjs` 扩到 10 项，新增「实时并发统计」：
  - 发起一个 900ms 慢速 chat 请求，进行中查 `/rate-limits/status`，断言 `global.current>=1`、`chat/completions.current>=1`。
  - 请求结束后再查，断言释放归 0（不泄漏）。

## 说明 / 未决

- 「全局并发」本轮仅作观测，不新增总闸门；如需**限制平台总流量**，可后续给 `RateLimitsConfig` 加 `global_max_concurrent` 并让 `enforceRateLimits` 增加一点 `conc:global` 闸门（与各层 AND）。
- 面板的「当前数」是进程内内存计数，多实例部署时不跨实例合并（单实例/单进程下准确）。
