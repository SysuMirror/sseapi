# 用量聚合查询 + 重排序（rerank）模型 + 按返回格式计费

## 背景

- 用量页此前只支持「按天 + 按模型」两个固定聚合，用户看不到按小时/按请求的粒度，也无法按维度（模型/类型/状态）下钻；一行 error 记录（Prompt/Completion/费用全 0）无法说明原因。
- 模型注册仅支持 chat / embedding / image_generation 三类，缺乏「重排序（rerank）」能力（如 SiliconFlow、Cohere、Jina、TEI 的 rerank 服务）。
- 计费要正确解析不同返回格式的 token：OpenAI Chat（`prompt_tokens/completion_tokens/total_tokens + prompt_tokens_details.cached_tokens + completion_tokens_details.reasoning_tokens`）、Anthropic Messages（`input_tokens/output_tokens`）、OpenAI Responses、以及 rerank 的 `usage` / `meta.tokens` / `meta.billed_units`。

## 目标

1. **用量多维度聚合查询**：新增 `/api/usage/aggregate`，支持 `granularity=day|hour|request` × 维度筛选（model/type/status/apiKeyId/time range），返回 totals / byTime / byModel / byStatus / request 明细分页。
2. **注册重排序模型**：新增 `rerank` 模型类型，平台对外 `/v1/rerank`（OpenAI 风格输入 `{model, query, documents, top_n, return_documents}`），内部按 `upstream_api_format` 适配多上游格式。
3. **按返回格式计费**：`readUsage` 兼容三种 token 形状；rerank 适配器从 `usage`/`meta.tokens`/`meta.billed_units` 提取 token；管理台探测明确显示「token 来源（上游 usage 或估算）」及 reasoning/cached 明细。

## 计费说明

- token 计费优先用上游返回的 usage（`prompt_tokens/completion_tokens/total_tokens`，或 `input_tokens/output_tokens`）；`cached_tokens` 取自 `prompt_tokens_details.cached_tokens`；DeepSeek 的 `reasoning_tokens` 属于 `completion_tokens` 一部分，无需额外拆分。
- 上游未返回 usage 时回退估算：chat/rerank 按文本长度占 1/4；路由 `usage_found` 标志在 `usage_logs.note` 记录 `usage_estimated`。
- 管理台探测会显示 `token 来源=上游 usage | 估算` 与 `found` 标志，便于核对。
