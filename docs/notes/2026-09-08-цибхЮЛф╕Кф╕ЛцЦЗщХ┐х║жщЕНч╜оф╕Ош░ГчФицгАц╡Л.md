# 模型上下文长度（context_length）配置与调用检测

## 背景
平台将模型统一转发到上游（OpenAI 兼容 / Anthropic 透传 / Responses）。若用户输入超过模型上下文上限，上游会报错甚至拒request，用户体验差且难以定位。需要一种机制：**注册/编辑模型时配置上下文长度，调用前检测输入 token，超限则拒绝并给出清晰错误**。

## 结论
1. `ModelRow` 新增 `context_length`（tokens，`0`=不限制）。仅对 `chat` 类模型生效（embedding/rerank/生图不入此检测）。
2. 调用前用 `estimateInputTokens()` 估算输入 token（按 JSON 文本长度粗算，只用于「是否超限」判断，不参与精确计费；计费仍走上游/Claude 估算）。
3. `context_length > 0` 且估算输入超出时：
   - `/v1/chat/completions`、`/v1/responses` → `400`，`error.type='context_length_exceeded'`，附 `exceed_tokens`。
   - `/v1/messages`（Claude）→ `400`，Anthropic 兼容的 `error` 形状。
   - 同时以 `status='context_exceeded'` 记一条 usage，便于排查。
4. 管理台模型列表卡片显示「上下文 xxx」徽标；模型创建/编辑表单新增「上下文长度」输入框（仅 chat 模型显示）。

## 关键路径
- 类型与迁移：`server/src/db.ts` → `ModelRow.context_length`，seed 默认 `0`，migrate 兜底 `if (m.context_length == null) m.context_length = 0`。
- 回归默认：`server/src/routes/admin.ts` `probeModelRow()` + `server/src/services/protocol-support.ts` `buildProbeRow()` 补 `context_length: 0`。
- 归一化：`server/src/services/model-catalog.ts` → `normalizeContextLength(v)`（非负整数，0/空=不限制）；`mapModelAdmin`/`mapModelConsole` 暴露 `contextLength`、`contextLimitEnabled`。
- 检测逻辑：`server/src/services/proxy-common.ts` → `estimateInputTokens()` / `contextLimitError()` / `contextLimitErrorBody()`；`server/src/routes/proxy.ts` 在 `chat/completions`、`messages`、`responses` 三种入口于转发前检测。
- 前端：`web/src/views/AdminView.vue` → 表单输入框、空值默认 `contextLength: 0`、保存体字段 `contextLength`、列表徽标 `.pill-ctx`。
- 部署压缩包：`sseapi-sseinfra.zip`（含 server/dist、web/dist）。

## 验证
- `cd server && npm run build` 通过；`cd web && npm run build` 通过。
- E2E `server/.e2e-test/context-length.mjs`：
  - 管理台保存 `contextLength=200` → `mapModelAdmin` 返回该值。
  - `ctx-100` 短输入 → 200 放行。
  - `ctx-100` 超长输入 → `400 context_length_exceeded`，未转发上游。
  - `ctx-0`（不限制）超长输入 → 200 放行并转发上游。
- 回归：`rate-limit.mjs`、`tool-cycle.mjs`、`usage-aggregate.mjs`、`dev-platform.mjs` 均通过。

## 未决事项
- 输入 token 估算为粗算（`JSON字符串长 / 2.5`），与上游真实 token 数可能有偏差；如需精确可引入 tokenizer，但当前仅用于「超限拦截」，够用。
- 上下文长度包含「输出预留」与否未定义：当前仅校验输入，未自动削减 `max_tokens`；如需预留输出空间可后续扩展。
